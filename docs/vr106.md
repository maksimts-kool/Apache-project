# VR 10.6 Projektiülesanne: Tsentraliseeritud Monitooringu Dashboardi Loomine Kibanas

## Eesmärk

Selle ülesande eesmärk on ühendada KawaiiEmoji projekti kolm peamist komponenti ühte Kibana monitooringu vaatesse:

- andmebaas: MySQL / `database`
- veebiserver: Apache / `webserver`
- rakenduse API: PHP API / `api`

Lõpptulemusena peab Kibanas olema üks keskne Dashboard, kus on näha kõigi kolme teenuse logid, logitasemete jaotus ning eraldi komponendipõhised vaated. Esialgu ehitame Dashboardi testandmete pealt Kibana Dev Toolsis. Hiljem hakkavad samasse indeksimustrisse logisid saatma LogForwardi skriptid või teenus.

## Meie projekti indeks

VR 10.5 konfiguratsiooni põhjal kasutame meeskonna indeksinimena:

```text
lidlempire_*
```

Testandmete jaoks loome konkreetse indeksi:

```text
lidlempire_probe_1
```

Kui õpetaja nõuab projekti nime põhist indeksit, siis alternatiivne variant on:

```text
kawaiiemoji_*
```

Käesolevas plaanis kasutame siiski `lidlempire_*`, sest see sobib kokku eelmises ülesandes kasutatud LogForwardi andmetega.

## Samm 2: Data View loomine Kibanas

Avada:

```text
Stack Management -> Data Views
```

Luua uus Data View:

- Name: `Lidlempire Logs`
- Index pattern: `lidlempire_*`
- Timestamp field: `@timestamp`

Pärast loomist avada:

```text
Discover
```

Kontrollida, et:

- ajavahemik katab kuupäeva `2026-04-26`
- logid on nähtavad
- väljad `level`, `service`, `message`, `@timestamp` on olemas

Kui kirjeid ei paista, tuleb Kibana ajafiltris valida näiteks:

```text
Apr 26, 2026 09:00 -> Apr 26, 2026 12:00
```

## Samm 3: Dashboardi loomine

Avada:

```text
Analytics -> Dashboard -> Create dashboard
```

Dashboardi nimi:

```text
Lidlempire Central Monitoring Dashboard
```

Soovitatav paigutus:

1. ülemine rida: üldised mõõdikud
2. keskmine rida: logitasemete ja teenuste jaotus
3. alumine osa: andmebaasi, veebiserveri ja API eraldi paneelid

## Nõutud visualiseeringud

### A. Üldvaade

#### 1. Message Count

Tüüp:

```text
Metric
```

Seadistus:

- Data view: `Lidlempire Logs`
- Metric: `Count`
- Filter: tühi
- Pealkiri: `Total Log Messages`

Mida see näitab:

- kõigi valitud ajavahemiku logisõnumite koguarvu

#### 2. Log Levels

Tüüp:

```text
Donut chart
```

Seadistus:

- Metric: `Count`
- Slice by: `Top values of level`
- Field: `level`
- Size: `5`
- Pealkiri: `Log Levels`

Oodatav jaotus:

- `INFO`
- `WARN`
- `ERROR`

#### 3. Logs By Service

Tüüp:

```text
Bar chart
```

Seadistus:

- Horizontal axis: `service`
- Vertical axis: `Count`
- Breakdown: `level`
- Pealkiri: `Logs By Service`

Mida see näitab:

- mitu logikirjet tuli andmebaasist, veebiserverist ja API-st
- milliste teenuste juures on rohkem `WARN` ja `ERROR` kirjeid

### B. Komponendipõhised paneelid

#### 1. Andmebaasi visuaal

Tüüp:

```text
Bar chart või Data table
```

Filter:

```text
service: "database"
```

Soovitatav seadistus:

- X-axis: `@timestamp`
- Y-axis: `Count`
- Breakdown: `level`
- Pealkiri: `Database Logs`

Mida vaadata:

- ühenduse timeoutid
- aeglased päringud
- constraint vead
- MySQL teenuse aktiivsus

#### 2. Veebiserveri visuaal

Tüüp:

```text
Bar chart
```

Filter:

```text
service: "webserver"
```

Soovitatav seadistus:

- X-axis: `@timestamp`
- Y-axis: `Count`
- Breakdown: `status_code` või `level`
- Pealkiri: `Webserver Traffic`

Mida vaadata:

- HTTP 200 päringud
- 401 ja 404 vead
- kliendi IP aadressid
- Apache access logide aktiivsus

#### 3. API / rakenduse visuaal

Tüüp:

```text
Line chart või Bar chart
```

Filter:

```text
service: "api"
```

Soovitatav seadistus:

- X-axis: `@timestamp`
- Y-axis: `Average of duration_ms` või `Count`
- Breakdown: `endpoint`
- Pealkiri: `API Activity`

Mida vaadata:

- API endpointide koormus
- aeglased päringud
- valideerimisvead
- 500 vead

## Kasulikud KQL filtrid Dashboardil

Kõik vead:

```text
level: "ERROR"
```

Kõik hoiatused ja vead:

```text
level: ("WARN" or "ERROR")
```

Ainult andmebaas:

```text
service: "database"
```

Ainult veebiserver:

```text
service: "webserver"
```

Ainult API:

```text
service: "api"
```

HTTP probleemid:

```text
status_code >= 400
```

Aeglased päringud:

```text
duration_ms >= 500
```

## Edasised sammud: päris logide suunamine

Kui Dashboard töötab testandmetega, tuleb ühendada päris logid. Meie projekti puhul on põhilised logiallikad:

- Apache access log: `logs/apache_access.log`
- Apache error log: `logs/apache_error.log`
- MySQL log: `logs/mysql.log`
- PHP API sündmused: rakenduse enda logimisfunktsioonid `app/logger.php` kaudu

LogForwardi või shipperi seadistuses tuleb kasutada sama loogikat:

- andmebaasi logid -> `service: "database"`
- Apache logid -> `service: "webserver"`
- API logid -> `service: "api"`
- indeks -> `lidlempire_*`
- timestamp -> `@timestamp`
- logitase -> `INFO`, `WARN`, `ERROR`

Nii hakkab sama Dashboard automaatselt kuvama ka reaalajas saabuvaid logisid.
